# BMR1 Guard

A tiny free, local macOS menu bar app that keeps the **Drop-BMR1** Bluetooth
speaker in output-only/A2DP mode — a replacement for SoundSource's per-device
"Output Only" feature for this one device.

## What it does

- **Blocks only Drop-BMR1 as an input device.** Whenever macOS makes Drop-BMR1
  the system-default input (typically right after the speaker reconnects), the
  guard immediately restores the **last valid input you actually used**
  (measured revert time: <82 ms).
- **Learns your microphone choice.** Switch freely among built-in, USB, wired,
  display, virtual, Continuity, or *other Bluetooth* microphones — every switch
  to a non-BMR1 device is accepted and remembered (persisted across restarts).
  There is no fixed priority list and no permanent lock on the MacBook mic.
- **Keeps the speaker on A2DP.** If the Drop-BMR1 output's nominal sample rate
  ever drops to the 16 kHz HFP path, the guard restores 44.1 kHz (measured:
  <150 ms) — deferring politely while something is actively recording from the
  BMR1 input so it never fights a live SCO link.
- **Costs nothing to run.** Idle CPU is 0.0 % (≈0.13 s of CPU per minute of
  wall time); it reacts to CoreAudio notifications rather than polling.
- **Leaves everything else alone.** Drop-BMR1 stays available (and default, if
  you chose it) as an *output*. Quitting the app restores stock macOS behavior
  instantly — no drivers, no daemons, no system modifications.

## How it works (and what it can't do)

An observation study of SoundSource's Output Only mode
([captures/FINDINGS.md](captures/FINDINGS.md)) showed it changes **no public
CoreAudio state**: the BMR1 input endpoint stays in the device list, no virtual
device appears, no formats change. Its observable effect is purely dynamic:
BMR1 is never allowed to remain the default input. BMR1Guard replicates exactly
that with CoreAudio property listeners + instant restore.

**Honest limitations:**

- The Drop-BMR1 microphone **still appears** in System Settings → Sound →
  Input. Neither this app nor (observably) SoundSource removes it. It just can
  never *stay* selected as default. (An app that explicitly opens the BMR1
  input device directly, bypassing the system default, can still trigger
  HFP; the guard then restores A2DP as soon as that recording stops. Codex and
  other default-input apps can never do this while the guard runs.)
- There is a sub-100 ms window between macOS switching the default and the
  guard reverting it. No real recording app can start IO within that window.
- Live SCO wedge-recovery (speaker silent until power-cycle) was deliberately
  **not** provoked during automated testing to avoid leaving the speaker
  unusable; the recovery logic (rate restore after input goes idle) is
  unit-tested.

## Menu bar

The speaker icon is filled while Drop-BMR1 is connected and guarded, outlined
when the speaker is absent, and dimmed when the guard is paused.

The app has a proper app icon (blue squircle speaker with a green check),
generated by `tools/makeicon.swift` into `Support/AppIcon.icns` — rerun that
script if you want to tweak the design.

**Single instance:** if a second copy is launched (e.g. one from `dist/` and
one from `/Applications`), the newer instance shows a brief notice and quits;
the copy that launched first keeps guarding. Ties at login are broken
deterministically, so two racing copies can never both exit. The menu shows current default input/output, the tracked ("last
good") input, the BMR1 output rate with A2DP/HFP indication, recent events,
Pause/Resume, Enforce Now, and Launch at Login.

## Build

```bash
./build-app.sh        # → dist/BMR1 Guard.app
swift test            # unit tests
```

## Install

```bash
cp -R "dist/BMR1 Guard.app" /Applications/
open "/Applications/BMR1 Guard.app"
```

Then (optional): menu bar icon → **Launch at Login**.

No special permissions are needed — the app never records audio, so no
microphone permission prompt; changing default devices is unprivileged.

To guard a different device later:
`defaults write com.youhan.bmr1guard BlockedDeviceName "Some Speaker"` and
relaunch.

## Uninstall

```bash
osascript -e 'quit app "BMR1 Guard"'
# if Launch at Login was enabled, turn it off in the menu first (or:
#   System Settings → General → Login Items → remove BMR1 Guard)
rm -rf "/Applications/BMR1 Guard.app"
defaults delete com.youhan.bmr1guard
```

Quitting alone already restores ordinary macOS audio behavior; the steps above
remove every trace.
